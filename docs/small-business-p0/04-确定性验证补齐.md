# 04 确定性验证补齐（P0-5）

## 1. 一句话原则

**工具说“已成功”不算成功；能拿文件系统/退出码核对上，才算成功。**

模型没有眼睛，工具返回什么它就信什么。如果工具因为磁盘满、路径被占用、权限不足而“嘴上说成功”，模型会把假成功写进回答，用户月底才发现账不对。这就是小企业版把“假成功”列为 P0 的原因。

## 2. 原来的验证覆盖

原来只核对 5 类文件操作：

| 工具 | 核对什么 |
| --- | --- |
| 写文件 | 文件存在、内容与参数一致（追加比对结尾） |
| 建目录 | 目录存在且是目录 |
| 移动 | 源消失、目标存在 |
| 复制 | 目标存在；文件还要大小与 SHA-256 一致 |
| 删除 | 原路径消失 |

## 3. 这次补了什么

### 3.1 `run_command`：退出码必须为 0

`run_command` 返回里带：

```text
命令：python script.py
退出码：1
标准错误：...
```

验证器会解析退出码：

- 退出码非 0 → 标 `[结果校验未通过]`，状态改为 `error`；
- 退出码为 0 → 标“命令自身认为成功”，但**不保证关键产物已经产生**。

为什么退出码 0 也不能算“完成”？因为很多脚本会吞异常后返回 0。真正的产物（文件数、行数、合计金额）仍需用文件工具再核对。验证器只做它能确定的那部分。

### 3.2 `copy_path`：大小与哈希都要对

复制最容易出现的假成功是“目标文件本来就在那里”。现在复制后会核对：

- 文件大小一致；
- 5 MB 以内的文件再比对 SHA-256；
- 不一致就标 `[结果校验未通过]`。

### 3.3 `computer_use` / `open_path`：标“未确认”

桌面点击、输入文字、打开程序之后，“世界有没有变成预期”无法用文件系统判定。硬要自动判定，只能让同一个模型看同一张截图——那是在放大同一个盲点。

所以这三类动作的结果会被标：

```text
[结果校验] 未确认：桌面动作没有确定性判据，无法自动核对；请人工看一眼结果
```

注意：它不会把状态改成 `error`，因为“无法验证”不等于“失败”；但它明确告诉模型和用户：**这是未确认，不要当成已完成。**

### 3.4 失败结果不重复校验

如果工具自己已经返回“写入失败”“不存在”“被拒绝”，验证器不会再去核对，避免把错误信息覆盖成“已核对”。

## 4. 验证结果怎么传给模型

```text
工具返回 → monitor_tool → verification.enrich_tool_message
  ├─ 核对通过：[结果校验] 已核对：...
  ├─ 无法核对：[结果校验] 未确认：...
  └─ 核对失败：[结果校验未通过] ... + status=error
```

模型在下一轮会看到这些附加文本；主提示词也明确要求：

- 看到 `[结果校验未通过]` → 必须如实说明，不得说“已完成”；
- 看到 `[结果校验] 未确认` → 必须让用户人工确认，不得说“已完成”。

## 5. 代码与用例

| 文件 | 作用 |
| --- | --- |
| `agent/tools/verification.py` | `VerificationResult`、各类 checker、`enrich_tool_message` |
| `agent/tools/middleware.py` | `monitor_tool` 在写审计前调用 enrich |
| `prompts/main_prompt.txt` | 第 17、23 条：以校验结论为准 |

用例（`AuditAndVerificationTest`）：

- 退出码 1 → `checked=True, ok=False`；
- 退出码 0 → `checked=True, ok=True`；
- 桌面动作 → `checked=True, ok=True, confirmed=False`。

```powershell
uv run python -m unittest tests.test_small_business_guard.AuditAndVerificationTest -v
```

## 6. 边界

1. **退出码 0 不是完成证明**：只代表命令自身认为成功。
2. **没有截图校验**：`computer_use` 仍需人看一眼；这是有意的“宁可报未确认，不报假成功”。
3. **验证器不抛异常**：校验本身失败时只记日志并跳过，避免校验把正常流程打断。
4. **文件内容比对有大小上限**：超过 5 MB 只核对存在性与大小，不逐字比对。
5. **验证器不能判断“语义正确”**：文件名改对了但改错了一个字，只有任务卡的成功判据（如“每个文件命中唯一供应商”）才能发现。

## 7. 一句话记住

**能确定性核对的，代码核对；核对不了的，明确标“未确认”交给人。**
