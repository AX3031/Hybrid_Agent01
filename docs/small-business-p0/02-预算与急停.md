# 02 预算与急停（P0-7）

## 1. 为什么需要“预算”

没有预算的 Agent 像一个没有话费上限的手机号：

- 模型可能在一个错误路径上反复调用工具；
- 每一步都在花钱，而且失败也会花钱；
- 用户往往到月底看账单才发现。

小企业版只要四个数字：**步数、时长、费用、急停**。这四个都能在代码里硬停，不依赖模型“自觉”。

## 2. 三个预算怎么算

| 预算 | 默认值 | 怎么算 | 超限后 |
| --- | --- | --- | --- |
| 步数 | 30 步 | 每真正执行一次工具 +1（等待人工确认不计） | 下一次模型调用前直接停止 |
| 时长 | 10 分钟 | 从任务开始到当前，扣除“等人工确认”的时间 | 同上 |
| 费用 | 2 元 | 模型返回 `usage_metadata` 时按配置单价累计；没有 usage 时只记录调用次数，不瞎扣 | 同上 |

默认值在 `config/agent.yml`：

```yaml
task_defaults:
  max_steps: 30
  max_minutes: 10
  max_cost_yuan: 2.0

model_prices:
  input_per_million: 2.0
  output_per_million: 6.0
```

任务卡可以逐任务覆盖这些值。任务卡里的预算优先级高于默认值。

## 3. 最关键的设计：停止不靠模型

很多系统会在提示词里写“预算用完请停止”。这只是一句建议，模型可以不听。

本项目的做法是**代码短路**：

```text
模型调用前 → guard_model 检查预算/急停
  ├─ 没超：正常调用模型
  └─ 超了：直接返回一条“任务已停止”的 AIMessage，不再调用模型
工具执行前 → guard_execute 再检查一次并计步
  ├─ 没超：执行工具
  └─ 超了：返回 status=error 的 ToolMessage，工具不执行
```

对应代码：`agent/guard/middlewares.py`、`agent/guard/state.py`。

## 4. 急停（kill switch）

### 4.1 界面上怎么用

左侧栏「安全开关」：

- 点「急停（当前动作做完就停）」→ 写一个 `STOP` 文件，并把当前任务标记为 stopping；
- 当前正在执行的**原子动作**会做完（避免半截文件），之后不再发起新工具、不再调用模型；
- 发布新任务会被拒绝，直到点「解除急停」。

### 4.2 外部怎么停

急停文件是 `STATE_DIR/STOP`（默认 `<项目根>/.agent_state/STOP`）。你也可以在终端里手动创建它：

```powershell
"手动急停" | Out-File -Encoding utf8 .agent_state\STOP
```

删除它即可解除。界面的按钮只是把这件事做得更容易。

### 4.3 急停为什么独立于模型

因为“模型遇到危险会停”不是控制，是祈祷。急停必须是文件/进程级开关，模型读不到也无权改。

## 5. 等待人工确认的时间不算预算

一个任务弹出确认卡片后，人去开会 20 分钟，回来再批准——这 20 分钟不应该算“任务跑了 20 分钟”。

实现：

- 任务挂起时保存快照；
- 恢复时把 `started_at` 向后平移“人离开的时长”；
- 所以时长预算只计算真正执行的时间。

## 6. 费用统计的诚实说明

`usage_metadata` 由模型供应商返回。如果供应商不返回：

- 不会用字符数瞎估算费用；
- 但仍然记录 `model_calls`、`input_tokens`、`output_tokens` 为 0；
- 费用上限不会触发，此时应依赖步数与时长上限。

这是一条已知限制，不是“费用一定准确”。

## 7. 代码与用例

| 文件 | 作用 |
| --- | --- |
| `agent/guard/config.py` | 读默认预算、模型单价 |
| `agent/guard/state.py` | 步数/时长/费用累计、STOP 文件、会话快照 |
| `agent/guard/middlewares.py` | `guard_model` 短路、`guard_execute` 计步、`track_model_usage` 记账 |
| `agent/react_agent.py` | 中间件顺序：`guard_model` 在模型前，`guard_preflight` 在确认前，`guard_execute` 在确认后 |
| `app.py` | 只读/急停按钮、任务状态提示 |

用例：

- `BudgetAndStopTest`：步数超限、急停触发/解除、急停未解除时拒绝新任务；
- `GuardMiddlewareOrderTest`：等待确认不扣步、批准后才扣步、预算超限不调用模型。

```powershell
uv run python -m unittest tests.test_small_business_guard.BudgetAndStopTest -v
uv run python -m unittest tests.test_small_business_guard.GuardMiddlewareOrderTest -v
```

## 8. 边界

1. **步数只统计工具调用**，不统计模型“空想”轮次；模型连续返回无工具调用的文本不会消耗步数。
2. **费用是估算**，见第 6 节。
3. **急停不杀进程**：它只是不再发起新动作。要强制结束，直接关掉 Streamlit 进程。
4. **工具调用还有 100 步硬上限**（`ToolCallLimitMiddleware`），作为任务卡缺省时的兜底。
5. **急停文件可被同用户程序删除**：这是“防手滑”级别，不是“防恶意程序”级别。

## 9. 一句话记住

**预算和急停必须写在代码里；写在提示词里的“请停止”不算数。**
