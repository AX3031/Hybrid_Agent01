# 01 批次号与整批回滚（P0-3）

## 1. 先讲一个生活类比

你去超市买一车东西，收银员给你一张**小票**。回家发现有一件买错了，你可以拿着小票把**这一次购物**的东西一起处理；而不是在垃圾桶里一件一件翻。

“批次号”就是这张小票：

- 一次任务 = 一个批次号（例如 `B20261027-110805-a1b2`）；
- 这次任务里的每一次写入、移动、复制、删除，都记在同一张“小票”上；
- 出错时点一下「撤销整批」，系统按**倒序**把这次任务改过的东西还回去。

## 2. 为什么原来的回收区不够

原来的 `.agent_trash` 只能撤销**一次删除**，`.agent_backup` 只能撤销**一次覆盖**。但真实任务往往是：

```text
改 3 个文件名 → 移动 10 个文件到归档目录 → 覆盖 2 个汇总表 → 删 1 个临时文件
```

如果第 12 步才发现搞错了，用户需要的是“把这一整套改动退回去”，不是逐个文件找回。批次号解决的正是这个问题。

## 3. 它到底记了什么

位置：项目根 `.agent_state/batches/<批次号>.jsonl`，一行一条 JSON，追加写。

| 操作 | 记什么 | 回滚怎么做 |
| --- | --- | --- |
| 写文件（覆盖） | 路径、覆盖前备份位置 | 把当前文件移走，恢复备份 |
| 写文件（新建） | 路径、原来不存在 | 把新文件移走（进回收区） |
| 追加 | 路径、追加前字节数 | 把文件截断回原大小 |
| 建目录 | 路径、原来是否存在 | 空目录则删除；非空则报失败 |
| 移动 | 源、目标 | 目标移回源 |
| 复制 | 源、目标 | 把副本移走 |
| 删除（回收区） | 原路径、回收区路径 | 从回收区移回原位置 |
| 永久删除 | 路径 | **不可逆**，只报告，不假装恢复 |

回滚是**倒序**执行的：最后做的先撤，避免“先撤父目录再撤子文件”这种顺序错误。

## 4. 怎么用

### 4.1 正常任务

不需要额外操作。只要任务是通过 Agent 发起的，写操作会自动带上当前批次号。确认卡片上会显示：

```text
批次号：B20261027-110805-a1b2（整批改动可在侧边栏「批次与回滚」里一次撤销）
```

### 4.2 撤销整批

1. 打开左侧栏「批次与回滚」；
2. 找到对应批次（显示任务名、时间、操作数、是否含永久删除）；
3. 展开「查看回放」可以先看它改了什么；
4. 勾选「我确认要撤销这一批」；
5. 点「撤销整批」。

结果会分三类告诉你：**已恢复 / 失败 / 不可逆**。失败和不可逆不会静默跳过。

### 4.3 回滚本身也会留痕

回滚会在同一批次文件末尾追加一条 `op=rollback` 记录，并写审计事件 `rollback`。这样“谁在什么时候撤销了什么”也能查到。

## 5. 代码在哪

| 文件 | 作用 |
| --- | --- |
| `agent/guard/journal.py` | 批次 ID、追加记录、读取摘要、整批回滚、回滚报告 |
| `agent/tools/os_tools.py` | 每个写工具成功后调用 `journal.record_*` |
| `agent/tools/safety.py` | 覆盖前备份、删除进回收区（回滚会复用） |
| `agent/guard/state.py` | 任务开始时生成批次号，并把任务卡快照写进同一批次 |
| `app.py` | 侧边栏批次列表、回放、一键回滚 |
| `utils/audit_logger.py` | `rollback` 事件 |

## 6. 验收用例

`tests/test_small_business_guard.py` 里的 `BatchRollbackTest`：

- 写入→移动→复制→删除→建目录，整批回滚后原文件内容恢复、副本消失、新目录消失；
- 追加写入回滚后文件回到追加前大小；
- 永久删除回滚后明确报“不可逆”，文件不会“复活”。

回归命令：

```powershell
uv run python -m unittest tests.test_small_business_guard.BatchRollbackTest -v
```

## 7. 边界与已知限制

1. **永久删除不可逆**：`delete_path(permanent=True)` 属于 R3，回滚只能报告，不能恢复。P0 里不建议使用永久删除。
2. **建目录只回滚叶子目录**：如果一次创建了多级父目录，回滚只尝试删除目标目录；父目录若为空可能残留。可以手动清理，或在下一版记录完整创建链。
3. **回滚冲突不覆盖**：如果原位置已经被新文件占用，回滚会报“失败”，不会把新文件覆盖掉。这是有意的 fail-safe。
4. **批次日志不是 WORM**：它防的是 Agent 工具写入和误操作，不防同一 Windows 用户下的恶意程序篡改。
5. **回滚不是时光机**：应用内状态（网页表单已填、剪贴板、已发出的消息）不在回滚范围；`run_command` 内部修改的文件、`open_path` 启动的程序、`computer_use` 操作的界面也不进入批次。

## 8. 一句话记住

**先有批次号，再开放写操作。** 没有整批回滚的自动化，不值得信任。
