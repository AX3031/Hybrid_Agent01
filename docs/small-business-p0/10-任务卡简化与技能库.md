# 10 任务卡简化与技能库（2026-10-27）

> 这一篇解释为什么删掉“每个任务先填一长串任务卡”，以及新增的“任务技能库”到底怎么用、怎么保证安全。
>
> 结论先说：**任务卡没有消失，而是变成“默认自动生成、需要时再展开高级设置”；机器判据变成可选项；技能库只保存步骤和截图，不自动执行。**

## 1. 为什么改

之前小企业版把任务卡做成“每个新任务必填”，安全上更严谨，但实际使用有三个问题：

1. 用户只是想问一句“打开记事本”，也要先写任务名、目标、成功判据、机器判据、范围、动作、预算；
2. 机器判据语法对普通用户不友好，写错会直接阻止启动；
3. 任务卡是一次性的，下一次做相同任务还要重新填，不能积累经验。

这轮改成两层：

- **快速任务卡（默认）**：直接按用户输入生成；预算用默认值；工作区、只读、人工确认、PIN 仍然生效。
- **自定义任务卡（高级）**：只在需要限定目录、预算、动作或写机器判据时展开。

同时新增技能库：把做过一次的任务步骤、关键截图、最终成果截图保存下来，下次作为参考。

## 2. 快速任务卡怎么生成

代码位置：`agent/guard/task_card.py` 的 `TaskCard.from_prompt()`。

输入：

```text
打开记事本，输入“本周工作总结”，保存到桌面
```

生成的快速卡大致是：

| 字段 | 默认值 |
| --- | --- |
| 任务名 | 输入第一行的前 40 个字 |
| 目标 | 用户完整输入 |
| 成功判据 | “按用户要求完成，并以工具实际返回结果和现场证据为准” |
| 机器判据 | 空（任务结束标记“未配置”，继续按人工确认验收） |
| 输入范围 | 空（工作区内） |
| 输出位置 | 空（工作区内） |
| 允许动作 | 全部动作类别 |
| 禁止动作 | 只默认禁止“提权” |
| 预算 | `config/agent.yml` 的 `task_defaults`（普通任务 30 步 / 10 分钟 / 2 元；要动鼠标键盘或启停应用时走 `desktop_*`，默认 60 步 / 20 分钟 / 5 元） |
| 有效期 | 120 分钟 |

### 2.1 为什么默认允许全部动作

因为目标是“能操作所有软件”。如果默认只允许“读”，用户每次都要手动加“桌面/命令/写”，又会回到填表疲劳。

### 2.2 一连串要求怎么拆

“打开微信，登录后给好友邓三三发个你好”这种输入，以前只被当成一个整句目标，模型很容易在第一件事上反复换坐标硬试，把预算烧光后后面两个子目标根本没开始。

现在 `TaskCard.from_prompt()` 会用 `split_subgoals()` 按标点与连接词（然后/接着/之后/，/。/；等）拆成子目标，写进任务卡并在提示词里列出：

```text
本次是一连串要求，拆成子目标逐项推进（只提醒顺序，不扩大权限）：
  1. 打开微信
  2. 登录后给好友邓三三发个你好
一次只做一个子目标：做完一个用事实确认后再进入下一个；
卡住（需要你登录、输入密码、扫码、付款这类）就停下来交给人。
```

配套三件硬约束（都在代码里，不靠提示词祈祷）：

- **子目标只是顺序提醒**，不是新的权限：允许动作、工作区、只读、确认、PIN 全部不变；拆不出两项以上时不显示这一段。
- **原地打转拦截**：`agent/guard/repeat_guard.py` 统计同一区域（60 px 内）的同类鼠标/键盘动作，第 3 次在工具结果里附「[重复动作提醒]」并提示改用 `app_open`/`app_open_start_menu`，第 6 次直接拒绝执行且不记步数。
- **登录类子目标交回给人**：提示词明确“需要登录/密码/验证码/扫码/付款时停下来请用户手动完成”，不允许模型猜测或搬运凭据。

真正的安全兜底不是任务卡的动作勾选，而是：

- 工作区域限制；
- 只读总开关；
- 所有写/命令/桌面动作仍然人工确认；
- 命令/GUI/永久删除属于 R2/R3，还需要 PIN；
- 批次与回滚；
- 审计日志。

### 2.2 为什么默认不禁止“发送/提交/付款”

`policy.py` 有一条保守规则：任务卡的禁止动作里只要包含“发送/提交/付款”，**所有 GUI 输入类动作都会被拒绝**，因为系统无法判断一次点击是否会触发提交。

快速卡如果把这三项默认写进去，用户会以为“打开软件”也被莫名拦截。所以快速卡只默认禁止“提权”；发送/付款的控制交给“人工确认 + PIN”。如果用户明确要求“这次绝对不许发送”，再到高级设置里把“发送/提交/付款”加进禁止动作，系统会保守拒绝所有 GUI 输入。

### 2.3 机器判据为什么变成可选

机器判据（`exists`、`file_count`、`sha256` 等）是确定性的，但它要求用户知道路径和格式，不适合作为默认门槛。现在的规则是：

- 不填：任务可以完成，验证事件显示“未配置机器判据，按人工确认和操作记录验收”；
- 填了但校验失败/无法核对：任务状态不能是 `finished`；
- 工具调用失败/被拒绝：任务状态也不能是 `finished`。

这是安全性与可用性的明确取舍：**快速任务不会自动验收，但不会阻止用户使用；需要强验收时再填判据。**

## 3. 自定义任务卡（高级）

侧边栏展开“任务卡（可选，默认自动）”，再打开“自定义任务卡（高级）”，才会出现表单。

表单现在只保留必要项：

```text
任务名（可选）
目标（可选；留空 = 使用本次输入）
成功判据（可选；留空 = 默认判据）
机器判据（可选；写入/命令类建议填）
输入范围（可选）
输出位置（可选）
允许动作（默认全部）
禁止动作（默认只禁止提权）
步数 / 时长 / 费用上限
```

“有效期、回滚说明、不确定时怎么办”不再要求用户填，直接使用安全默认值。需要恢复自动模式时，点“恢复自动任务卡”。

## 4. 技能库是什么

代码位置：`agent/skill_library.py`。

技能库不是“保存一段脚本自动重放”，而是保存一次任务的经验：

| 字段 | 作用 |
| --- | --- |
| 技能名 / 适用场景 | 方便搜索和理解 |
| 大概步骤 | 从工具调用记录生成的人话摘要，可编辑 |
| 关键截图 | 从本次任务截图中选择，复制进技能库 |
| 最终成果截图 | 任务完成后的结果画面 |
| 任务卡预设 | 上次允许动作、输出位置、机器判据、预算等，供参考 |
| 使用次数 | 记录被参考过多少次 |

### 4.1 步骤是怎么生成的

`steps_from_operations()` 只保存：

```text
1. 打开应用：记事本
2. 输入文字：***（已脱敏，8 字符）
3. 点击屏幕：(800, 450)
```

不会保存：

- 工具返回正文；
- 剪贴板内容；
- `type_text` / `clipboard_set` 的原文；
- `run_command` 的命令原文（只写“命令内容已省略”）；
- `open_path` 的 URL 原文（避免把查询参数里的 token 写进技能）。

这样技能库不会变成第二个秘密泄漏面。

### 4.2 截图怎么保存

- `computer_use` 的截图结果现在会在文本里附带本地截图路径，界面用这条路径找出“本次任务截图”；
- 如果本次操作记录没带出路径，候选列表会退回到 `logs/omnipilot/screenshots` 下最近的截图，方便手动选；
- 只复制 `.png` / `.jpg` / `.jpeg` / `.webp`；
- 单个文件不超过 10 MB；
- 复制到 `data/task_skills/screenshots/<技能 id>/`；
- 原始截图删掉不影响技能库；
- 截图可能含密码、验证码、聊天记录，保存前界面会提醒用户自己确认。

### 4.3 怎么复用

1. 直接描述任务即可：开启“自动参考匹配的技能”（默认开）后，系统会按目标推荐技能并带上参考步骤；
2. 想强制指定时，在技能库选择一个技能 → “下次任务参考此技能”（手动优先于自动）；
3. 生成的快速任务卡会带上“可复用技能参考（只作步骤提示，执行前仍要按现场核对）”，回答下方会显示“本轮参考技能：…”，侧边栏可一键关掉自动推荐；
4. 仍然走当前任务卡、人工确认和 PIN。

技能不会自动执行，也不会把旧步骤当成“已执行”。如果旧步骤和新软件界面不一致，模型必须按当前截图和实际结果重新判断。

### 4.4 修改与删除已保存技能

- 选中一个技能后点“编辑此技能”，表单会加载它的名字/适用场景/步骤/截图，改完点“保存修改”会回写到同一个技能；
- **同名保存视为更新**：未选编辑时直接保存一个新名字会新建；重复保存同一个名字不会堆出一堆同名技能，而是更新那一个；
- 删除需先勾选“我确认删除这个技能”，再点“删除技能”；刷新重开页面后仍可删除（删除只操作技能库自己的目录）。

### 4.5 按子目标拆开存（schema v2）

之前的问题：把“打开微信→又发消息”整条链存成一条技能，下次只说“打开微信”就匹配不上、也不认识。

现在的做法：

- 保存时自动用 `split_skill_candidates()` 拆成多条（依托任务卡已有的 `split_subgoals`），每条都有自己能命中的名字；
- 界面上是一个可折叠的“按子目标分别保存（N 条技能）”，可勾选要哪几条再批量保存；
- 每条技能多了三个字段：
  - `goal_match`：什么时候推荐它（如 `打开微信`、`wechat`）；
  - `intents`：建议动作（如 `app_open：微信`、`click：微信 → 登录`）；
  - `verify`：完成后可机器核对的条件（如 `exists|D:/输出/报表.xlsx`）。
- 自动推荐的打分：**标题（名字/匹配词）看包含关系**，描述只当弱信号——避免“从开始菜单打开软件”因为描述里写了“打开微信”而被每个打开软件的任务都命中；
- 旧 `skills.json` 不需要手改：读取时自动补上 `schema=2/goal_match=[技能名]/intents=[]/verify=[]`，下次保存时写回新结构。

## 5. 数据放在哪、谁能写

```text
data/task_skills/
├── skills.json              # 技能列表（steps / goal_match / intents / verify / 任务卡预设 / 使用次数）
└── screenshots/<id>/        # 关键截图 / 最终成果截图副本
```

- 已加入 `.gitignore`，不进入版本库；
- `safety.py` 把 `data/task_skills` 列为项目保护路径：Agent 工具不能写，`run_command` 引用 `task_skills` 也会被拒绝；
- 用户可以在界面删除技能；删除只操作技能库自己的目录。选中技能还可“编辑此技能”，改名/改步骤/换截图后回写同一个技能。

## 8. 还剩什么问题

1. **技能步骤是“参考”，不是可执行工作流**：没有参数化、条件分支、失败重试；复杂软件仍需模型现场判断。
2. **截图只给人看**：复用时不自动把截图发给模型，也还没有截图标注/裁剪；技能详情可预览已保存的截图。
3. **技能库没有版本管理**：同名技能更新会覆盖步骤，旧版本不保留。
4. **技能库没有鉴权**：本机用户都能打开界面看到保存的步骤和截图。
5. **GUI 仍需 PIN**：没有设置 PIN 时，R2/R3 动作不能批准；这是“第二主体”的设计，不是本轮简化掉的。
6. **快速卡默认动作很宽**：安全边界靠工作区、确认、PIN、回滚、审计；如果企业要求最小权限，请用自定义任务卡限定动作和输出目录。

## 9. 一句话总结

**把“填表”降级为“可选的精细控制”，把“经验”升级为“可复用的技能参考”；安全边界仍由代码、确认和 PIN 承担，不交给模型自觉。**
