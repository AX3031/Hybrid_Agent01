# 03 任务卡与只读模式（P0-1 / P0-2）

## 1. 任务卡是什么

把任务卡想成**装修合同**：

- 目标：把厨房改成什么样；
- 成功判据：水电验收怎么算过；
- 允许范围：只能动厨房，不能拆承重墙；
- 预算：多少钱、多少天；
- 不确定时：停下来问房主，不能自己猜。

没有合同，工人“顺手”把客厅也改了，你很难追责。任务卡就是给 Agent 的合同。

## 2. 任务卡的字段

| 字段 | 例子 | 作用 |
| --- | --- | --- |
| 任务名 | 发票归档 | 审计和批次列表里的标识 |
| 使用者 | 小李（财务） | 出问题找谁 |
| 目标 | 把下载/发票下的 PDF 按“年月_金额_供应商”改名并移动到归档/2026 | 让模型知道做什么 |
| 成功判据 | 归档文件数 = 源文件数；无重名 | **人话判据**，给模型和人看 |
| 机器判据 | `file_count` + 目录 + 数量；`absent` + 路径 | **可选**；填了任务结束由代码执行 |
| 输入范围 | `C:\Users\finance\Downloads\发票` | 只允许在这里读 |
| 输出位置 | `D:\归档\2026` | 只允许在这里写 |
| 允许的动作 | 读、写、移动、删除 | 越界工具会被守卫层拒绝 |
| 禁止的动作 | 发送、提交、付款、提权 | 明确不做；自定义卡保留这些语义词时，GUI 输入类动作会被保守拒绝；快速卡默认只禁止提权 |
| 预算 | 30 步 / 10 分钟 / 2 元 | 见 02 篇 |
| 有效期 | 120 分钟 | 过期不再执行 |
| 回滚说明 | 只回滚文件类改动 | 和回滚边界一起展示 |
| 不确定时 | 标记 UNKNOWN 并停下来问人 | 给模型一个“我不知道”的出口 |

## 3. 怎么启用

默认不需要填表：在输入框正常描述任务，界面会调用 `TaskCard.from_prompt()` 自动生成快速卡。

需要精细控制时，再打开左侧栏「任务卡（可选，默认自动）」→「自定义任务卡（高级）」：

1. 任务名/目标/成功判据都可以留空，留空用输入和默认值；
2. 机器判据可选；写入/命令类建议填；
3. 输入范围/输出位置可选（必须是工作区域内的绝对路径）；
4. 允许动作默认全部；禁止动作默认只禁止“提权”；
5. 点「启用自定义任务卡」。

**每个新任务仍然必须有任务卡**：快速卡也是卡；直接调用 API 时没有卡会被 `start_task()` 拒绝。

启用后：

- 任务卡会追加到系统提示词末尾（模型能看到）；
- 任务卡快照会写进批次日志和审计（事后能查“谁授权了什么范围”）；
- 下一次任务开始时生效；
- 自定义卡用完记得点「恢复自动任务卡」，避免下一件不相关的事也套用这张卡。

## 4. 任务卡怎么被强制执行

任务卡不是“提示词建议”，而是**代码级检查**：

```text
guard_preflight（人工确认前）
  ├─ 没有任务卡 → 拒绝；界面会先自动生成快速卡
  ├─ 动作类别不在允许列表 → 拒绝
  ├─ 动作在禁止列表 → 拒绝
  ├─ 禁止发送/提交/付款时，GUI 输入类动作 → 保守拒绝
  ├─ 读取路径不在输入范围 → 拒绝
  ├─ 写入路径不在输出位置 → 拒绝
  └─ 预算/急停 → 拒绝
```

拒绝会返回一条 `status=error` 的工具消息，模型能看到原因，但工具不会执行。模型想“换个工具绕过”也会被同一套检查拦住。

**没有任务卡时**：新任务不能启动；界面会自动生成快速卡，API 调用需要显式传入。快速卡默认允许全部动作，但工作区、只读、人工确认、PIN 和批次回滚仍然生效。

**任务结束时**：配置了机器判据才由 `agent/guard/criteria.py` 执行；未配置标 `not_required`，按人工确认验收；未通过/未确认，或任务中有工具失败/被拒绝，不能算完成。

检查代码在 `agent/guard/policy.py` 的 `check_task_card()` 与 `preflight_reason()`。

## 5. 只读模式是什么

只读模式是**总闸**：保留读取、搜索、截图能力，禁用所有会改变本机的动作。

被禁用的工具/动作：

- `write_text_file`、`create_directory`、`move_path`、`copy_path`、`delete_path`；
- `run_command`（命令可能写文件）；
- `open_path`（可能启动程序）；
- `computer_use` 的鼠标、键盘、剪贴板写入、应用启停。

仍然允许：

- 列目录、读文件、搜文件名/内容；
- 看系统信息、看进程；
- 截图、看屏幕尺寸、找图、等待、读剪贴板、列出应用。

## 6. 只读模式怎么开

两种方式：

1. 左侧栏「安全开关」→ 打开「只读模式」；会写回 `config/agent.yml`，立即生效；
2. 临时演练：设置环境变量 `AGENT_READ_ONLY=1`（优先级高于配置文件）。

关闭：界面关掉开关，或把 `config/agent.yml` 的 `read_only` 改为 `false`。

代码里做了**两层**拦截：

- 中间件 `guard_preflight` 在工具执行前拒绝；
- `os_tools.py` 的每个写工具开头再检查一次 `check_read_only()`，防止有人绕过中间件直接调用工具。

## 7. 一个完整例子

任务卡：

```yaml
任务名: 发票归档
使用者: 小李
目标: 把下载/发票下的 PDF 按年月_金额_供应商改名并移动到归档/2026
成功判据:
  - 归档目录文件数 = 源目录文件数
  - 无重名文件
机器判据:
  - file_count|D:\归档\2026|10
  - absent|D:\归档\2026\临时文件
输入范围: C:\Users\finance\Downloads\发票
输出位置: D:\归档\2026
允许的动作: [读, 写, 移动, 删除]
禁止的动作: [发送, 提交, 付款, 提权]
预算: 30 步 / 10 分钟 / 2 元
回滚说明: 只回滚文件类改动；命令/GUI 不在回滚范围
```

模型如果尝试写 `D:\归档\2027`，会被拒绝：

```text
[守卫层拒绝] 任务卡规定只能写入 D:\归档\2026，`write_text_file` 指向 D:\归档\2027，已拒绝。
```

## 9. 边界

1. **任务卡不能修改自己的预算或范围**：模型只能读提示词里的卡，不能改卡；越界由代码拒绝。
2. **成功判据仍需人写对**：人话判据写得含糊（“整理好”），模型无法替你判定；机器判据只证明文件/字段对上，不证明业务语义正确。
3. **只读模式不防命令副作用**：`run_command` 在只读模式下已被禁用，但同用户的其他程序不受影响。
4. **任务卡不替代工作区**：任务卡范围是工作区的子集；工作区仍是硬边界。
5. **路径比较会解析 8.3 短路径与 `..`**，但不防符号链接/junction 逃逸；这是已知技术债。
6. **GUI 语义禁令是保守策略**：禁止发送/提交/付款会拒绝所有 GUI 输入类动作；`run_command`/`open_path` 仍靠人工确认 + PIN。

## 10. 一句话记住

**任务卡管“这次做什么”，只读模式管“现在能不能写”；两者都在代码里，不在提示词里。**
