# 06 单任务全局锁（P0-8）

## 1. 为什么需要锁

一台 Windows 桌面只有：

- 一个鼠标焦点；
- 一个剪贴板；
- 一个前台窗口；
- 一套正在被操作的文件。

两个任务同时跑，会互相抢焦点、互相覆盖剪贴板、把对方的文件移走。失败看起来是“随机的”，排障会非常痛苦。

小企业版不做队列系统，只做一件最小的事：**同一时刻只允许一个任务操作本机。**

## 2. 锁长什么样

位置：`<项目根>/.agent_state/task.lock`（可用 `AGENT_STATE_DIR` 改目录）。

内容示例：

```json
{
  "pid": 12345,
  "token": "8f3c...",
  "thread_id": "user_001",
  "acquired_at": 1793000000.0
}
```

获取方式：`os.open(..., O_CREAT | O_EXCL)`，这是操作系统级的“原子创建”，两个进程同时抢只会有一个成功。

## 3. 第二个任务会看到什么

```text
另一个任务正在操作本机（会话 user_001，开始于 2026-10-27 11:08:05）。
请等它结束，或在确认它已经卡死后删除 .agent_state/task.lock。
```

界面会显示成黄色提示，不会执行任何工具。

## 4. 进程崩溃留下的锁怎么办

如果进程被强制结束，锁文件会残留。下一次任务会检查：

- 锁里的 PID 是否还存在（`psutil.pid_exists`）；
- 锁文件是否超过 6 小时；
- 任意一条成立 → 视为过期，自动清理并重新获取。

这比“永远卡死”好，但仍建议：确认没有任务在跑时再手动删除锁文件。

## 5. 锁和“等待人工确认”的关系

- 任务运行期间持有锁；
- 工具挂起等待人工确认时，本次流结束，锁会释放；
- 用户批准后 `resume_stream` 重新获取锁，继续同一个批次和预算。

这意味着：在“等待确认”的间隙，另一个任务理论上可以开始。它不会改到同一个批次（批次号按任务隔离），但如果你希望**确认期间也禁止其他任务**，可以把锁改成跨确认持有；当前 P0 选择“确认间隙释放”，避免用户离开导致锁永久占用。

```powershell

```

## 7. 边界

1. **单机文件锁**：只在同一台机器、同一个状态目录生效；不是分布式锁。
2. **不防同用户手动删除**：用户可以在任务管理器外删掉锁文件；这是“防并发误操作”，不是“防恶意”。
3. **过期时间 6 小时**：长任务超过 6 小时会被误判为过期；当前小企业版任务应在分钟级完成。
4. **进程内还有 `_CURRENT` 状态**：文件锁防跨进程，进程内状态防同一进程的重复任务；两者互补。
5. **等待确认间隙可被插队**：见第 5 节，这是有意的取舍。

## 8. 一句话记住

**一张桌子一次只能一个人动；锁不是排队系统，是防互相踩手。**
