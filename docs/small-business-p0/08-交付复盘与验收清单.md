## 4. 反思：哪些做得好

1. **先造尺子再改代码**：每个能力都有对应用例，且验证脚本会留证据 JSON；不是“感觉能跑”。
2. **拒绝把提示词当边界**：只读、任务卡、预算、审批全部在代码里，模型改不了。
3. **失败安全**：PIN 未设置 → 不允许批准；回滚冲突 → 报失败不覆盖；永久删除 → 报不可逆不假装恢复。
4. **中间件顺序正确**：预检在人工确认前，扣步在确认后；有用例证明“等待确认不扣步”。
5. **状态目录保护**：`.agent_state`、`.agent_backup`、`.agent_trash` 禁止 Agent 写入；审批目录禁止读写。

## 5. 反思：哪些还不够

1. **PIN 仍不是真正的“第二主体”**：同一 Windows 用户下的恶意程序可以绕过；这是小企业版的明确取舍。
2. **批次日志不是 WORM**：同用户可改；只能防误操作，不能防蓄意。
3. **费用上限可能不触发**：供应商不返回 usage 时不会估算；需要看供应商能力。
4. **建目录回滚只删叶子目录**：多级父目录可能残留。
5. **任务卡范围不防符号链接逃逸**：工作区本身也有这个技术债。
6. **GUI 动作仍无法自动验证**：只能标“未确认”，需要人看一眼；自定义卡保留“禁止发送/付款”时会保守拦截 GUI 输入，但快速卡默认不包含这些词；命令/URL 仍靠人工。
7. **单任务锁在等待确认间隙释放**：另一个任务可以插队；批次隔离，但桌面资源仍可能冲突。
8. **没有真实端到端 30 次运行数据**：目前是离线用例，不等于真实场景成功率；下一步要按第 6 周要求跑 30 次。
9. **批次回滚只覆盖文件类写操作**：`run_command` 内部修改的文件、`open_path` 和 `computer_use` 的应用内状态不在回滚范围，只能靠任务卡范围与确认前核对降低风险。
10. **`.env` 等秘密文件仍可读**：本轮只禁止项目写和技能库写，没有禁止秘密文件读取；已确认下一步应默认拒绝秘密文件读取，业务确需时走独立敏感读取确认 + PIN + 脱敏，但尚未实现。
11. **日志仍可能含原始参数**：`log_approval` 写原始 actions，`read_text_file` 摘要可能落盘；需要统一脱敏。
12. **快速卡放宽了自动验收**：机器判据现在可选；没填时不会假装“自动完成”，但仍能按人工确认交付；需要强验收请填判据。
13. **技能库是本地明文**：步骤虽脱敏，截图仍可能含隐私；当前只做到 Agent 禁写与 gitignore，还没有加密或自动清理。

## 6. 下一版（P1）建议顺序

1. **真实场景 30 次端到端**：记录成功率、接管次数、假成功、不可逆事故；只修 bug，不加功能。
2. **手机/IM 带外审批**：把 PIN 从同机升级为真正第二通道。
3. **UIA 控件树通道**：先 UIA，坐标兜底；减少截图成本与误点。
4. **应用支持矩阵**：只登记 3 个应用，各 5 条回归用例。
5. **漂移测试阶梯**：改文案 → 挪位置 → 改主题/DPI，记录在哪一级失效。
6. **截图降采样与保留期**：控制存储与隐私面。
7. **备份演练**：每天复制 `logs/` 与 `.agent_state/` 到第二块盘/网盘，每季度恢复一次。

## 7. 一页 runbook

| 现象 | 先做什么 | 再做什么 |
| --- | --- | --- |
| 任务卡住不动 | 看侧边栏批次/操作记录 | 急停 → 回滚 → 重跑 |
| 说“权限不足” | 检查工作区是否包含该路径 | 加目录，不要加整个盘 |
| 审批按钮灰掉 | 检查是否设置了审批口令 | 运行 `scripts/setup_approval_pin.py` |
| 审批一直不弹 | 检查是否有另一个任务持有锁 | 等它结束，或确认卡死后删除 `task.lock` |
| 磁盘满 | 清 `.agent_trash` 与旧截图 | 设置保留期（建议 30 天） |
| 账单暴涨 | 查截图数量与重试次数 | 降低任务卡步数/时长/费用上限 |
| 回滚报“失败” | 看回滚报告里的冲突路径 | 人工处理冲突文件，不要强行覆盖 |
| 回滚报“不可逆” | 确认是否用了永久删除 | 以后改用回收区删除 |
