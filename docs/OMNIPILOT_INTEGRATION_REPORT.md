## 1. 先说结论

这次做了四件事：

1. **调研 OmniPilot**：搞清它是什么、有哪些能力、怎么安装、能不能本地跑。
2. **选型**：决定“只复用它的工具层”，不嵌套它自己的 Agent。
3. **落地**：新增一个 `computer_use` 工具，包含 18 个桌面动作，接入现有的人工确认、操作记录、审计日志和工作区安全体系。
4. **验证**：真实跑通了“只读动作直接执行”“截图前弹确认”“拒绝后不执行”“批准后模型能看懂截图”“截图不把 base64 写进日志”等关键链路。

现在这个 Agent 除了原来的文件、命令、进程能力，还能：

- 截屏并让模型“看见”屏幕；
- 点击、双击、右键、拖拽、滚动鼠标；
- 输入文字、按键、按快捷键；
- 读写剪贴板；
- 启动、关闭、列出应用；
- 在屏幕上按模板图片找位置。

但所有这些“会动电脑”的动作，默认都要你点确认。

## 3. 三个主角：项目、OmniPilot、模型

### 3.1 当前项目是什么

可以把当前项目理解成：

> 一个会“自己决定调用哪个工具”的本地电脑助手。

它的核心是一个 **Agent**。Agent 不是模型本身，而是“模型 + 工具 + 规则 + 记忆”的组合：

- **模型**：负责理解你说的话、决定下一步做什么；
- **工具**：负责真正干活，比如读文件、跑命令、截图、点鼠标；
- **规则**：比如“文件只能在某个目录里操作”“危险操作要你确认”；
- **记忆**：记住同一会话之前聊过什么。

当前项目已经有的工具：

- 看系统信息、列目录、读文件、搜文件；
- 写文件、建目录、移动、复制、删除；
- 执行系统命令；
- 查进程；
- 百度联网搜索；
- 一些业务查询和报告工具。

它缺的是：**看屏幕、动鼠标、敲键盘、管应用**。这正是 OmniPilot 能补的。

### 3.2 OmniPilot 是什么

可以把 OmniPilot 理解成：

> 一个现成的“桌面遥控器工具箱”，里面有 41 个按钮，每个按钮对应一个真实电脑动作。

它的按钮包括：

- 截图、看屏幕分辨率、在屏幕上找图；
- 点鼠标、双击、右键、拖拽、滚动；
- 输入文字、按键、按快捷键；
- 读/写剪贴板；
- 启动/关闭/列出应用；
- 跑命令、跑 Python、读写文件、下载网页、发通知；
- 还有它自己的权限系统、审计日志、模型供应商适配。

它本身也是一个完整 Agent，可以自己接模型、自己循环、自己弹权限确认。

### 3.3 模型是什么

当前项目用的是 `qwen3.5-flash`，通过阿里云百炼的 OpenAI 兼容接口调用。

它有两个关键能力：

1. **Function Calling / 工具调用**：能决定“我要调用 `computer_use`，参数是 `{"action": "screenshot"}`”。
2. **视觉输入**：能接收图片，所以截图可以作为工具结果给它看。

> 注意：模型本身在云端。截图会作为图片发送给模型。也就是说，**工具在本机跑，但“看图”这一步默认会经过阿里云**。如果你要完全离线，需要把模型换成 Ollama / LM Studio 的本地视觉模型。

## 4. 为什么没有把 OmniPilot 整个塞进来

这是这次最重要的设计决定。

### 4.1 两种做法

**做法 A：把 OmniPilot 整个 Agent 当成一个工具**

```text
用户 → 当前 Agent → computer_task("打开记事本并输入 hello") → OmniPilot Agent → 它的工具 → 电脑
```

**做法 B：只复用 OmniPilot 的工具（本次采用）**

```text
用户 → 当前 Agent → computer_use(action="screenshot") → OmniPilot 的 Screenshot 工具 → 电脑
```

### 4.2 为什么选 B

用大白话比喻：

- 做法 A 是“你雇了一个助理，助理又雇了一个助理”。两个助理都要理解任务、都要做决定，成本翻倍，而且你只能看到外层助理的汇报，看不到内层助理具体点了哪里。
- 做法 B 是“你雇了一个助理，给他配了一套遥控器”。助理还是原来那个，只是多了一个能操作桌面的遥控器。

具体原因：

| 维度 | 做法 A：嵌套 Agent | 做法 B：只复用工具 |
| --- | --- | --- |
| 模型调用 | 至少翻倍 | 不变 |
| 中间步骤 | 内层隐藏，外层只看到最终结果 | 每一步都走当前项目的操作记录 |
| 人工确认 | 只能确认“整个任务”，粒度粗 | 每个截图/点击/输入都能单独确认 |
| 审计日志 | 两套系统，难对齐 | 一套系统，统一记录 |
| 出错排查 | 不知道是内层还是外层的问题 | 直接看当前项目的工具事件 |
| 依赖复杂度 | 要配置 OmniPilot 的模型、权限、会话 | 只 import 它的工具类 |

所以最终选择 B。OmniPilot 在这个项目里的角色不是“另一个 Agent”，而是“一个本地的桌面能力库”。

## 6. 实现方法（小白版）

### 6.1 一张图看懂

```text
你
 │
 ▼
Streamlit 页面（app.py）
 │
 ▼
ReactAgent（LangChain create_agent）
 │
 ├── 模型：决定“我要调用 computer_use，action=screenshot”
 │
 ├── 人工确认中间件：如果是危险动作，先弹卡片问你
 │
 ▼
computer_use 工具（agent/tools/computer_use.py）
 │
 ├── 参数校验 / 安全检查 / 动作分发
 │
 ▼
OmniPilot 的本地工具类（Screenshot / Click / TypeText / OpenApplication ...）
 │
 ▼
真实 Windows 桌面
 │
 ▼
结果回到模型（文字，或者文字 + 图片）
```

### 6.2 一个工具，18 个动作

为什么是一个工具，而不是 18 个工具？

- 给模型看的工具越少，它越不容易“选错工具”；
- 18 个动作共享同一套参数校验、确认策略、日志；
- 以后要加动作，只改一个文件。

动作分四组：

| 组 | 动作 | 一句话解释 | 默认确认 |
| --- | --- | --- | --- |
| 屏幕 | `screenshot` | 截屏，并把图片给模型看 | ✅ 要 |
| 屏幕 | `screen_size` | 只问屏幕多大 | ❌ 不用 |
| 屏幕 | `locate_image` | 拿一张模板图去屏幕上找 | ❌ 不用 |
| 屏幕 | `wait` | 等几秒，让界面反应完 | ❌ 不用 |
| 鼠标 | `click` | 在 (x, y) 点一下 | ✅ 要 |
| 鼠标 | `double_click` | 双击 | ✅ 要 |
| 鼠标 | `right_click` | 右键 | ✅ 要 |
| 鼠标 | `move_mouse` | 只移动，不点 | ✅ 要 |
| 鼠标 | `drag` | 从 A 拖到 B | ✅ 要 |
| 鼠标 | `scroll` | 滚轮 | ✅ 要 |
| 键盘 | `type_text` | 向当前焦点窗口输入文字 | ✅ 要 |
| 键盘 | `press_key` | 按一个键，比如回车 | ✅ 要 |
| 键盘 | `hotkey` | 按组合键，比如 Ctrl+S | ✅ 要 |
| 剪贴板 | `clipboard_get` | 读剪贴板 | ✅ 要 |
| 剪贴板 | `clipboard_set` | 写剪贴板 | ✅ 要 |
| 应用 | `app_open` | 启动应用 | ✅ 要 |
| 应用 | `app_close` | 关闭应用 | ✅ 要 |
| 应用 | `app_list` | 列出运行中的应用 | ✅ 要 |

> “确认”不是模型自己弹，而是当前项目的 `HumanInTheLoopMiddleware` 在工具真正执行前把图挂起，等你在页面上点“我确认，执行”。

### 6.3 截图是怎么让模型“看见”的

普通工具返回的是一段文字。截图返回的是两段内容：

```python
[
    {"type": "text", "text": "截图已保存到 ...，坐标原点在左上角"},
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}
]
```

- `text` 是给模型看的说明；
- `image_url` 是图片本身；
- `data:image/png;base64,...` 是把图片编码成一长串文字，方便塞进消息里。

LangChain 的 `ToolMessage` 支持这种“文字 + 图片”的列表。模型收到后，就能像人看截图一样看图。

### 6.4 为什么每次都要确认

因为桌面控制的风险和文件操作不一样：

- 点错一个坐标，可能点到“删除”“发送”“支付”；
- 输入错一个窗口，文字可能落到聊天框、终端、密码框；
- 截图可能包含密码、聊天记录、邮件；
- 关闭应用可能丢失未保存的数据。

所以除了三个“只读、低风险”的动作，其余全部要确认：

- 只读：`screen_size`、`locate_image`、`wait`
- 需要确认：截图、读剪贴板、列出应用，以及所有鼠标/键盘/剪贴板写入/应用启停；其中鼠标/键盘/剪贴板写入/应用启停属于 R2，还要输入审批口令（PIN）。

确认卡片会用大白话写：

- 要做什么（“点击屏幕”“输入文字”“截取屏幕画面”）；
- 目标是什么（坐标、应用名、文字预览）；
- 有什么风险（“可能误点其他按钮”“可能覆盖剪贴板”“截图可能含隐私”）。

### 6.5 安全护栏

除了确认，还加了几层自动护栏：

| 护栏 | 做什么 |
| --- | --- |
| 应用黑名单 | `app_open` 拒绝 cmd、PowerShell、Windows Terminal、WSL、bash、cscript、mshta、rundll32、regedit、diskpart、bcdedit 等 |
| cmd 元字符拦截 | 应用名/参数里不允许 `& | < > ^ % ( ) " ;`，防止 `cmd /c start` 被拆成多条命令 |
| 系统进程保护 | `app_close` 拒绝 explorer、svchost、lsass、winlogon 等，连 `expl`、`svch` 缩写也拦 |
| 路径守卫 | `locate_image` 的模板路径、`app_open` 的路径型名称必须在工作区内 |
| 参数上限 | 文字 10000 字符、剪贴板 20000 字符、等待 10 秒、点击 1–3 次、按键 1–20 次 |
| 日志脱敏 | 截图 base64 不写日志；`type_text`/`clipboard_set` 参数和 `clipboard_get` 结果定向脱敏 |
| 单任务预算 | 默认 30 步 / 10 分钟 / 2 元；100 步硬上限，防止模型循环；R2/R3 桌面动作还需审批口令 |

### 6.6 坐标为什么不会偏

这是一个很容易被忽略的坑。

OmniPilot 默认会把截图缩到最长边 1568px，但屏幕是 1920×1080。如果模型看着 1568 宽的图，估了一个“1000”的坐标，实际屏幕上 1000 的位置和图上的 1000 不是同一个地方，点击就会偏。

本次的处理：

- 屏幕不超过 600 万像素（大约 2560×2340）：**直接发送原图**，图片像素 = 屏幕像素，模型看到哪就点哪。
- 超过 600 万像素（比如 4K）：回退到缩放图，并在结果文字里明确写：
  `图片已缩小到 1568×882，屏幕实际为 3840×2160；点击坐标 = 图片坐标 × 2.4490`
- 1080p 实测：原图 PNG 只有 281KB，比缩放图还小，所以“发原图”既准又省。

### 6.7 日志和操作记录

- 操作记录：聊天页“本次操作记录”，用人话写“截取屏幕画面”“点击屏幕”“输入文字”。
- 审计日志：`logs/audit_YYYYMMDD.jsonl`，每次工具调用一行 JSON；含 `batch_id / step_no / reversibility / approver`。
- 截图 base64 不会写进日志，只写占位符 `[图片已附加给模型，base64 已省略]`。
- 文字输入和剪贴板写入的参数、剪贴板读取的结果，在审计日志里会显示为 `***（已脱敏，N 字符）`。

## 7. 怎么用

### 7.1 启动

在项目根目录执行：

```powershell
uv sync
uv run streamlit run app.py
```

浏览器打开 Streamlit 输出的地址。

### 7.2 第一次试什么

建议按这个顺序试：

0. **先设置审批口令**（否则鼠标/键盘/应用启停等 R2 动作无法批准）：
   - `uv run python scripts/setup_approval_pin.py`
1. **只读，不弹确认**：
   - “当前屏幕分辨率是多少？”
2. **需要确认，但不会动鼠标**：
   - “看看当前屏幕。”
   - 会弹确认卡片，点“我确认，执行”后，模型会看到截图并描述。
3. **需要确认，动应用**：
   - “打开记事本。”
4. **需要确认，动鼠标键盘**：
   - “在屏幕上找到记事本，输入 hello。”
   - 这会拆成多步：截图 → 点击 → 输入，每一步都会确认。

### 7.3 一次截图操作会发生什么

以“看看当前屏幕”为例：

1. 你输入问题。
2. 模型决定调用 `computer_use`，参数 `{"action": "screenshot"}`。
3. 系统检查：截图需要确认。
4. 页面弹出确认卡片：
   - 标题：截取屏幕画面
   - 说明：截取整个屏幕交给模型查看。截图可能包含密码、聊天记录等隐私内容。
   - 风险：截图可能包含密码、聊天记录、邮件等隐私内容，并会作为图片发送给模型分析。
5. 你点“我确认，执行”。
6. 系统截屏，保存到 `logs/omnipilot/screenshots/`，把图片作为工具结果发给模型。
7. 模型看图，回答屏幕上有什么。
8. 操作记录里出现“截取屏幕画面”，结果摘要里只显示文字，不显示 base64。

如果第 5 步你点“不要执行”：

- 工具不会执行；
- 模型会收到“用户拒绝”的消息；
- 主提示词要求它必须说“操作被拒绝，未执行”，不得编造屏幕内容；
- 操作记录里也不会出现截图结果。

### 7.4 常用例子

```text
看看当前屏幕。
当前屏幕分辨率是多少？
打开记事本。
把 Chrome 关掉。
现在有哪些程序在运行？
看看剪贴板里是什么。
把“hello world”复制到剪贴板。
点击屏幕上 (800, 450) 的位置。
在输入框里输入 hello，然后按回车。
按 Ctrl+S 保存。
把窗口从 (400, 300) 拖到 (900, 600)。
向下滚 5 格。
```

### 7.5 如果点不准

按顺序尝试：

1. 先让它“截个屏”，确认目标窗口在前台、坐标没被遮挡；
2. 让它“看看屏幕分辨率”，确认不是多显示器/缩放导致的偏移；
3. 用 `locate_image`，给一张按钮/图标的模板 PNG，让它在屏幕上找；
4. 把目标窗口移到主显示器，避免多屏坐标问题；
5. 如果仍然不准，给更明确的描述，比如“点浏览器右上角的三个点，大概在 (1500, 80)”。

### 7.6 怎么关闭/回滚

如果你不想用桌面控制，按从轻到重三种方式：

**方式一：只在 Agent 里停用（推荐，最快）**

打开 `agent/react_agent.py`，把 `tools` 列表里的 `computer_use` 删掉，同时把 `CONFIRM_TOOLS` 里的 `"computer_use"` 和 `_HITL_CONFIG["computer_use"]` 的 `when` 删掉。这样模型就看不到这个工具了。

**方式二：删掉工具文件**

删除 `agent/tools/computer_use.py`，并删掉 `react_agent.py` 里的 import 和注册。

**方式三：卸载依赖**

```powershell
uv remove omnipilot-agent
```

> 注意：`pyautogui`、`pyperclip`、`pillow` 可能还会留在环境里，因为别的依赖也可能用它们。要彻底清理，需要检查 `uv.lock`。

## 8. 不能怎么用

这一节很重要。下面这些不是“不建议”，而是“不要”：

### 8.1 不要让它输入密码、支付密码、验证码

- `type_text` 会把文字输入到当前焦点窗口；
- 如果焦点窗口不对，密码可能落到聊天框、搜索框、日志里；
- `type_text` 会覆盖剪贴板，密码可能残留在剪贴板；
- 截图也可能把密码框拍进去。

如果确实需要输入敏感信息，建议你自己手动输入，或者只让 Agent 操作到“输入框已聚焦”这一步。

### 8.2 不要在无人值守的情况下运行

- 所有危险动作都要人点确认；
- 如果你用脚本自动点“确认”，就等于把最后一道防线拆了；
- 不要把它接到“自动点击确认”的循环里；
- 不要在远程桌面无人看管时让它自己跑 GUI 任务。

### 8.3 不要把它当沙箱

- 它不是虚拟机，不是容器，不是低权限账户；
- 它和你在同一个 Windows 用户下运行；
- 它能看到/操作你当前用户能操作的东西；
- 工作区限制只对文件路径生效，对“屏幕上已经打开的窗口”没有隔离；
- 确认卡片是最后一道防线，不是技术沙箱。

### 8.4 不要让它关闭系统关键进程

- `app_close` 已经拒绝 explorer、svchost、lsass、winlogon 等；
- 但不要尝试用缩写、改名、其他进程名绕过；
- 关闭系统进程可能导致桌面崩溃、未保存数据丢失、系统不稳定。

### 8.5 不要用它启动终端/脚本宿主

- `app_open` 已经拒绝 cmd、PowerShell、Windows Terminal、WSL、bash、cscript、mshta 等；
- 这是为了防止“打开终端 → 输入命令”绕过 `run_command` 的黑名单；
- 需要执行命令时，请用 `run_command`，它有确认和危险命令黑名单。

### 8.6 不要用于多用户/生产/高价值数据

- 当前没有登录、鉴权、多租户；
- 会话 ID 可以被改；
- 工作区、日志、记忆都没有加密；
- 不要用在客户隐私、金融、医疗、生产服务器上；
- 不要把它暴露到公网。

### 8.7 不要在无桌面会话的服务器上跑 GUI

- 截图、鼠标、键盘、应用操作都需要真实桌面；
- 无头/SSH 服务器只能跑文件、命令等非 GUI 工具；
- Linux 需要 X11/Wayland、scrot 等依赖；
- macOS 需要辅助功能/屏幕录制权限。

### 8.8 不要指望 100% 精准

- 没有控件树、没有 OCR、没有窗口选择器；
- 主要靠截图 + 坐标 + 模板匹配；
- 多显示器、DPI 缩放、窗口移动、动画未完成都可能让坐标偏移；
- 复杂界面建议拆成小步骤，一步步截图确认。

### 8.9 不要用它删除/修改重要文件

- 文件类操作请用现有的 `delete_path` / `write_text_file` / `move_path`；
- 它们有工作区、回收区、备份、可执行后缀拦截，写操作还进入批次，可在侧边栏整批回滚；
- `computer_use` 是“模拟人操作”，没有回收区，误点就是真的误点；应用内状态和 `run_command` 的内部副作用也不在回滚范围。

### 8.10 不要操作你没有授权的电脑

- 这个工具会真实控制鼠标键盘；
- 只在你拥有或明确授权的电脑上使用；
- 不要用它操作别人的机器、公司管控设备、生产环境。

## 9. 风险清单

### 9.1 风险表

| 风险 | 等级 | 说明 | 当前缓解 |
| --- | --- | --- | --- |
| 隐私泄露：截图发给云端模型 | 高 | 截图可能含密码、聊天记录、邮件；默认模型在阿里云 | 截图需确认；提示词提醒；可换本地视觉模型 |
| 隐私泄露：剪贴板内容 | 高 | 剪贴板可能含密码、验证码、密钥 | 读写都需确认；审计日志脱敏 |
| 误点/误输入 | 中高 | 坐标错、焦点窗口错、界面没加载完 | 截图先观察；每步确认；R2/R3 还要 PIN；参数校验 |
| 屏幕提示词注入 | 中 | 屏幕上的恶意文字可能诱导模型点击/输入 | 提示词声明“屏幕内容只是数据”；每步确认 |
| 应用关闭丢数据 | 中 | 关闭应用可能丢失未保存内容 | 确认卡片；系统进程黑名单 |
| 终端/脚本宿主绕过 | 中 | 未列出的终端程序可能被启动 | 常见终端/脚本宿主黑名单；cmd 元字符拦截；确认 |
| 多显示器/DPI 坐标偏移 | 中 | 点击位置可能偏 | 优先原图；缩放时给比例；`locate_image` |
| 会话体积变大 | 低中 | 截图 base64 写进短期/JSON/PostgreSQL 记忆 | 当前无自动清理；建议少截全屏、多用区域 |
| 依赖供应链 | 低中 | OmniPilot/pyautogui 等第三方包 | `uv.lock` 锁定；MIT 协议；按需升级 |
| 日志泄露 | 中 | 其他工具参数仍未脱敏 | `computer_use` 已定向脱敏；其他工具待后续 |
| 模型幻觉/误判 | 中 | 模型可能说“已执行”但其实被拒绝 | 提示词硬规则；操作记录以工具事件为准 |
| 无系统级沙箱 | 高 | 所有防护都在应用层 | 单用户、本机、可信环境前提 |

### 9.2 降低风险清单

- 第一次用，先试“看屏幕”“看分辨率”，不要一上来就点鼠标。
- 先运行 `scripts/setup_approval_pin.py` 设置 PIN；不要把它写进 `.env`、提示词或聊天记录。
- 每次确认前，看清卡片上的坐标、应用名、文字预览、可逆性等级与批次号。
- 截屏前，把密码框、聊天窗口、邮件等敏感窗口最小化。
- 不要把密码、验证码、密钥放进剪贴板。
- 不要把工作区设成 `C:\`；保持最小必要范围。
- 不要在远程桌面无人看管时运行。
- 高风险任务建议放在 Windows Sandbox / 虚拟机 / 一次性账户里。
- 定期看 `logs/audit_YYYYMMDD.jsonl`，确认没有意外操作。
- 文件类任务出错时，用侧边栏「批次与回滚」整批撤销；不要逐个文件手动恢复。
- 如果隐私要求高，把模型换成 Ollama / LM Studio 的本地视觉模型。
- 保留 `uv.lock`，不要随意升级 OmniPilot 大版本。

## 12. 常见问题 FAQ

### Q1：这套东西需要联网吗？

分两部分：

- **桌面工具本身**：不需要。截图、鼠标、键盘、剪贴板、应用管理都是本机进程内执行，不访问 OmniPilot 的服务器。
- **模型**：默认需要。当前模型 `qwen3.5-flash` 在阿里云百炼，截图会作为图片发给它。
- **联网搜索**：只有你明确让它搜网页时才用百度搜索。

如果你要“连模型也完全离线”，需要把 `model/factory.py` 指向 Ollama / LM Studio 的本地视觉模型。

### Q2：它会不会自己乱点？

不会“自己”乱点。模型可以决定“我想点哪里”，但所有有副作用的动作都会先弹确认卡片，你不点“我确认，执行”，它就不会执行。

前提是：你不要写脚本自动点确认，也不要在无人值守时让它跑。

### Q3：截图去哪了？

- 截图文件保存在 `logs/omnipilot/screenshots/`；
- 图片会作为工具结果发给模型；
- 操作记录和审计日志里只显示文字，不显示 base64；
- `logs/` 已被 `.gitignore` 忽略，不会进 Git；
- 你可以手动清理这个目录。

### Q4：为什么每次都要确认？

因为桌面控制的风险比读文件高：

- 点错位置可能点到“删除”“发送”“支付”；
- 输入错窗口可能把文字打到聊天框、终端、密码框；
- 截图可能含隐私；
- 关闭应用可能丢数据。

确认卡片是最后一道防线。

### Q5：能不能让它自动点，不要确认？

技术上可以改代码，但**不建议**。如果你确实要无人值守，应该放在 Windows Sandbox / 虚拟机 / 一次性账户里，并接受“误点/误输入”的风险。

### Q6：为什么点不准？

常见原因：

1. 多显示器：坐标可能按主屏算；
2. DPI 缩放：系统缩放 125%/150% 会让坐标偏移；
3. 窗口没在前台；
4. 界面动画还没加载完；
5. 模型看图估坐标有误差。

处理顺序：截图确认 → 看分辨率 → `locate_image` → 把窗口移到主屏 → 手动给更明确的坐标。

### Q7：能不能让它输入密码？

不建议。`type_text` 会输入到当前焦点窗口，并覆盖剪贴板。密码可能落到错误窗口、残留在剪贴板、被截图拍进去。

如果确实需要，建议你自己输入，或者只让 Agent 操作到“输入框已聚焦”。

### Q8：支持 Mac/Linux 吗？

OmniPilot 和 pyautogui 代码层面是跨平台的，但**本项目只在 Windows 上验证过**。macOS 需要辅助功能/屏幕录制权限；Linux 需要 X11/Wayland、scrot 等依赖。

### Q9：会不会很贵？

桌面工具本身不额外调用模型，所以不会因为“多了一个工具”而多花钱。但：

- 截图会作为图片输入，消耗图片 token；
- 每一步 GUI 动作都可能触发一次模型调用；
- 长任务（截图 → 点击 → 截图 → 输入 …）会累积 token。

具体费用按百炼的计费规则算。

### Q10：怎么彻底删掉？

三种方式，从轻到重：

1. 从 `agent/react_agent.py` 的 `tools` 列表删掉 `computer_use`；
2. 删除 `agent/tools/computer_use.py`，并删掉 import；
3. `uv remove omnipilot-agent`。

### Q11：为什么模型说“已截图”，但其实被拒绝了？

这是一个真实出现过的问题，已经修复：

- 拒绝后，工具结果里会写“User rejected...”；
- 主提示词明确要求：拒绝后必须说“操作被拒绝，未执行”，不得编造屏幕、窗口、剪贴板内容；
- 实测修复后，模型会正确回答“截图操作被拒绝，因此无法看到当前屏幕内容”。

### Q12：为什么截图会发给阿里云？

因为当前模型 `qwen3.5-flash` 是云端模型。截图要让它“看见”，就必须把图片作为输入发给它。

如果你不希望截图离开本机，有两个选择：

1. 不用截图功能；
2. 把模型换成 Ollama / LM Studio 的本地视觉模型。

## 13. 术语表

| 术语 | 大白话解释 |
| --- | --- |
| Agent | 会自己决定“下一步调用哪个工具”的调度员 |
| Tool / 工具 | 给调度员的一个个按钮，比如“截图”“点击”“读文件” |
| Function Calling | 模型输出“我要调用哪个工具、参数是什么”的能力 |
| HITL | Human-in-the-loop，危险操作前先让人确认 |
| 中间件 / Middleware | 在模型或工具调用前后插入的逻辑，比如日志、脱敏、确认 |
| Content Block | 消息里的一段内容，可以是文字，也可以是图片 |
| base64 | 把图片变成一长串文字，方便塞进消息里 |
| 工作区 / Workspace | 给助手划定的文件活动范围，默认是用户目录 + 项目根 |
| 审计日志 | 每次工具调用的结构化记录，写在 `logs/audit_*.jsonl` |
| 提示词注入 | 文件/网页/屏幕里的恶意文字，试图让模型执行不该做的事 |
| DPI 缩放 | Windows 的显示缩放，125%/150% 会让坐标换算变复杂 |
| Checkpointer | 会话记忆的存储后端（内存 / JSON / PostgreSQL） |
| 沙箱 | 把程序关在隔离环境里，出错也不影响真实系统；本项目**没有** |

## 14. 后续建议

按优先级：

### P0：先用起来，别急着自动化

- 先用“看屏幕”“看分辨率”建立信任；
- 每次确认前看清卡片；
- 不要在无人值守时跑 GUI 任务；
- 不要把密码/验证码/密钥交给 `type_text`。

### P1：补齐体验

- 给 `computer_use` 加一个配置开关（`config/agent.yml` 里的 `computer_use.enabled`），不用改代码就能停用；
- 截图前自动检测敏感窗口并遮罩（密码框、聊天窗口）；
- 给 `locate_image` 增加 opencv 可选依赖说明/自动安装提示；
- 给截图增加自动清理策略（按天数/大小）。

### P2：提升准确率

- 接入 Windows UI Automation（UIA）或 OCR，用“控件/文字”定位，而不是纯坐标；
- 多显示器/DPI 校准；
- 截图区域裁剪 + 坐标偏移自动换算；
- 动作后自动截图验证，形成“观察 → 动作 → 验证”的闭环。

### P3：安全加固

- 应用白名单/签名校验，替代纯黑名单；
- 敏感窗口检测；
- 审计日志全量脱敏 + 轮转 + 防篡改；
- 高风险任务放进 Windows Sandbox / 虚拟机；
- 本地视觉模型选项，避免截图出本机。
