# 电脑助手功能说明

> 这份文档面向两类读者：
>
> - **普通使用者**：读第 1–7 节，用大白话解释"能做什么、怎么用、有什么风险"。
> - **开发者**：读第 8 节，包含工具参数、代码位置、安全阈值和扩展方法。
>
> 代码实现：[agent/tools/os_tools.py](../agent/tools/os_tools.py)　确认逻辑：[agent/react_agent.py](../agent/react_agent.py)　界面：[app.py](../app.py)

---

## 1. 一句话认识它

它是一个跑在你自己电脑上的对话助手。你用日常语言告诉它想做什么，它会调用本机能力去完成：

- 想知道电脑状态，它去查；
- 想找文件，它去翻；
- 想改文件、删文件、执行命令，它会先把"要做什么"摆给你看，你点批准它才动手。

它不是一个"全自动接管电脑"的程序。**所有会改变电脑状态的操作，都需要你点一次确认。**

---

## 2. 先搞懂一件事：两种操作

| 类型 | 包括什么 | 它的行为 | 你需要做什么 |
| --- | --- | --- | --- |
| **查看类（只读）** | 看配置、看目录、读文件、搜文件、看进程 | 直接执行，不打扰你 | 无 |
| **修改类（有副作用）** | 写文件、建目录、移动、复制、删除、执行命令、打开程序 | 先停下，弹出确认卡片 | 点「批准执行」或「拒绝执行」 |

为什么这么分？

因为"看一眼"和"改一下"的风险完全不同。看错了最多是信息不准；删错了、覆盖错了，可能找不回来。所以查看类不打断你，修改类必须你点头。

## 3. 六种"查看"能力

### 3.1 查看电脑配置和空间

**你可以这样说：**

- "这台电脑什么配置？"
- "C 盘还剩多少空间？"
- "我的桌面在哪个路径？"

**它会告诉你：**

- 操作系统版本、电脑名称、当前登录用户
- CPU 核心数
- 内存用了多少、总共多少、占比
- 每个磁盘用了多少、总共多少、占比
- 桌面、下载、文档三个文件夹的完整路径

**实际返回示例：**

```text
操作系统：Windows 10（AMD64）
主机名：Broh0
当前用户：Administrator
用户目录：C:\Users\Administrator
CPU 核心数：12
内存：已用 9.8GB / 共 15.8GB（61.7%）
Desktop 目录：C:\Users\Administrator\Desktop
磁盘：
  C:\ 已用 76.7GB / 共 80.0GB（95.9%）
  D:\ 已用 188.0GB / 共 396.6GB（47.4%）
```

**它不会做的事：**

- 不会去读你的密码、浏览记录、聊天记录。
- 不会偷偷上传任何东西。

---

### 3.2 查看某个文件夹里有什么

**你可以这样说：**

- "看看桌面有什么文件"
- "列出 D 盘项目文件夹的内容"
- "看看下载目录，隐藏文件也要看"

**它会告诉你每个项目的：** 名称、是文件还是文件夹、大小、最后修改时间。

**实际返回示例：**

```text
目录：C:\Users\Administrator\Desktop（共 3 项）
[目录] 项目资料 | - | 2026-10-20 14:22
[文件] 报告.docx | 1.2MB | 2026-10-24 09:15
[文件] 笔记.txt | 820B | 2026-10-25 21:03
```

**几个细节：**

- 文件夹排在前面，文件排在后面，各自按名称排序。
- 最多显示 500 项，超过会提示"共多少项"。
- 默认不显示以 `.` 开头的隐藏项；说"隐藏文件也要看"才会显示。
- 它只过滤以点开头的项，不检测 Windows 的"隐藏属性"。

---

### 3.3 读取一个文本文件的内容

**你可以这样说：**

- "帮我读一下 D 盘那个说明.txt"
- "这个文件太长了，先读前 5000 个字"
- "从第 20000 个字开始往后读"

**它会返回：** 文件路径、总长度、本次读的是哪一段，然后是正文。

**实际返回示例：**

```text
文件：D:\项目\说明.txt（总长度 8 字符，本次返回 0-8）
hello 电脑
```

**为什么要有"分段"？**

因为有些文件很长，一次性全塞给 AI 会超出它的处理能力，也会浪费钱。所以它默认一次最多返回 20000 个字符，你可以让它接着往后读。

**它的限制：**

- 一个文件最多只读前 2 MB，再大就会截断。
- 二进制文件（比如图片、exe、压缩包）会被拒绝，提示"这是二进制文件"。
- 编码会依次尝试 UTF-8、GBK、Latin-1，所以中文一般不会乱码。

---

### 3.4 按文件名找文件

**你可以这样说：**

- "在 D 盘找所有 .py 文件"
- "找一下名字里带'报告'的文件"
- "在项目文件夹里找 report 开头的文件"

**它会返回：** 匹配到的文件完整路径列表。

**几个细节：**

- 会递归翻遍所有子文件夹。
- 不区分大小写，`Report` 和 `report` 都能匹配。
- 如果你只说"报告"，它会自动理解成"名字里包含报告"。
- 默认最多返回 50 个，最高可以调到 200 个。
- 只匹配**文件名**，不匹配文件夹名。
- 会跳过以 `.` 开头的隐藏文件夹。

---

### 3.5 按内容搜文件

**你可以这样说：**

- "在项目里搜一下 TODO"
- "哪些 .log 文件里出现了 timeout"
- "在桌面所有 txt 里找'合同'两个字"

**它会返回：** 哪一行、哪个文件、那一行的内容。

**实际返回示例：**

```text
在 D:\项目 下命中 2 处（已扫描 18 个文件）：
D:\项目\main.py:42: # TODO 改成配置文件
D:\项目\README.md:8: TODO 补充安装说明
```

**几个细节：**

- 是"包含这两个字"的匹配，不是正则表达式。
- 不区分大小写。
- 每行最多显示 300 个字符。
- 默认只搜 50 条结果，最高 200 条。
- 会跳过大于 5 MB 的文件。
- 最多扫描 5000 个文件，防止扫整个硬盘卡死。
- 底层单文件最多读 2 MB，所以 2–5 MB 的文件只搜了前半部分。

---

### 3.6 看哪些程序最占内存

**你可以这样说：**

- "哪个程序最占内存？"
- "列一下内存占用前 10 的进程"

**它会返回：** 进程 ID、程序名、内存占用、所属用户。

**实际返回示例：**

```text
内存占用最高的 20 个进程：
PID 1234 | chrome.exe | 850.2MB | DESKTOP\Administrator
PID 5678 | Code.exe | 420.8MB | DESKTOP\Administrator
```

**几个细节：**

- 只按**内存**排序，不显示 CPU 占用百分比。
- 默认 20 个，最多 100 个。
- 系统进程或权限不足的进程会被跳过，不会报错。

## 4. 七种"修改"能力

这一节的所有操作，**都会弹出确认卡片**。卡片上会写清楚"用哪个功能、传了什么参数"，你点批准才会执行。

### 4.1 写入或追加文本

**你可以这样说：**

- "在桌面新建 note.txt，写'明天开会'"
- "往 D 盘日志.txt 末尾追加一行 hello"

**它会做什么：**

- 文件不存在就创建；父文件夹不存在也会自动建好。
- `write` 模式覆盖整个文件，`append` 模式加在末尾。
- 只写 UTF-8 文本。

**返回示例：**

```text
已写入 5 个字符到 C:\Users\Administrator\Desktop\note.txt
```

**风险提示：** `write` 模式会覆盖原文件内容。如果你说"写"但本意是"加"，一定要说清楚"追加"。

---

### 4.2 创建文件夹

**你可以这样说：**

- "在 D 盘建一个'备份'文件夹"
- "创建 D:\项目\2026\10 月"

**它会做什么：**

- 文件夹不存在就创建，已存在也算成功。
- 多级目录会一次性建好。

---

### 4.3 移动或重命名

**你可以这样说：**

- "把桌面的 a.txt 改名成 b.txt"
- "把这个文件挪到 D 盘备份文件夹"

**它的规则：**

- 目标写的是一个已存在的文件夹 → 会把文件挪进那个文件夹。
- 目标写的是一个不存在的路径 → 当重命名处理。

**返回示例：**

```text
已移动：C:\...\a.txt -> C:\...\b.txt
```

**风险提示：** 如果目标位置已经有同名文件，Windows 行为是覆盖或报错，具体取决于系统。重要文件建议先复制再删。

---

### 4.4 复制文件或文件夹

**你可以这样说：**

- "把这个文件复制到 D 盘备份"
- "把整个项目文件夹复制一份"

**它的规则：**

- 目标是已存在文件夹 → 复制进去。
- 复制文件夹会连同里面的内容一起复制。
- 复制文件会保留修改时间等属性。

**和移动的区别：** 复制之后原文件还在，移动之后原位置就没有了。

---

### 4.5 删除文件或文件夹

**你可以这样说：**

- "删掉桌面的 test.tmp"
- "把 D 盘那个空文件夹删掉"
- "把这个文件夹连同里面的东西一起删掉"

**它的规则：**

- 删文件：直接删。
- 删空文件夹：直接删。
- 删非空文件夹：**必须明确说"连同里面的内容一起删"**，它才会用递归删除。

**风险提示：**

- 这是风险最高的功能。
- 删除不进回收站，删了就没了。
- 确认卡片上会显示完整路径和"是否递归"，请务必看一眼再点批准。

---

### 4.6 执行系统命令

**你可以这样说：**

- "执行 ipconfig 看看网络"
- "运行 dir D:\项目"
- "执行 ping baidu.com"

**它会返回：** 命令本身、退出码、标准输出、标准错误。

**实际返回示例：**

```text
命令：ipconfig
退出码：0
标准输出：
Windows IP 配置
...
```

**几个细节：**

- 输出最多返回 8000 个字符，超出会截断。
- 中文输出会自动尝试 UTF-8 和 GBK 解码，一般不会乱码。
- 默认最多等 60 秒，可以要求更长（最长 600 秒），超时会提示。
- **它没有命令黑名单，也没有沙箱。** 你批准什么，它就执行什么。确认卡片是唯一防线。

**风险提示：** 不要批准你不理解的命令。尤其是带 `del`、`format`、`rd /s`、`reg delete` 的命令。

---

### 4.7 用默认程序打开文件、文件夹或网址

**你可以这样说：**

- "打开 D 盘项目文件夹"
- "打开这个网址 https://example.com"
- "用默认程序打开这个 PDF"

**它会做什么：**

- 文件或文件夹：交给 Windows 资源管理器/默认程序打开。
- 网址：交给默认浏览器打开。
- 如果路径不存在，会直接告诉你，不会打开。

## 5. 确认卡片长什么样

当它要做修改类操作时，聊天区会出现这样一块内容：

```text
┌──────────────────────────────────────────────┐
│ 以下操作会修改你的电脑，请确认后执行：        │
│                                              │
│ {                                            │
│   "tool": "delete_path",                     │
│   "args": {                                  │
│     "path": "C:\\Users\\...\\test.tmp",      │
│     "recursive": false                       │
│   }                                          │
│ }                                            │
│                                              │
│ [ 批准执行 ]        [ 拒绝执行 ]              │
└──────────────────────────────────────────────┘
```

**怎么看这张卡片：**

- `tool` 是它想用的功能名，比如 `delete_path` 就是"删除"。
- `args` 是它准备传的参数，重点是 `path`（操作哪个文件）和 `recursive`（是否递归）。
- 点「批准执行」：操作真正发生。
- 点「拒绝执行」：操作不会发生，它会告诉你"用户拒绝了"。

**当前限制：**

- 一次只能全部批准或全部拒绝。如果模型一次发起了多个操作，不能只批准其中一部分。
- 不能修改参数后再执行。发现路径不对，应该点拒绝，然后重新说一遍需求。

## 6. 它绝对不会碰的地方

为了保护系统，写、删、移动这几类操作会自动拒绝以下位置：

| 位置 | 说明 |
| --- | --- |
| `C:\Windows` | 系统目录 |
| `C:\Program Files` | 已安装软件 |
| `C:\Program Files (x86)` | 32 位软件 |
| `C:\ProgramData` | 系统公共数据 |
| `C:\`、`D:\` 等盘符根目录 | 防止误删整盘 |

如果你让它删这些地方的文件，它会直接回复：

```text
拒绝删除系统保护目录：C:\Windows\...
```

**注意：** 这条限制只管"写、删、移动"。**读取不受限制**，它仍然可以读系统目录里的文本文件。

## 7. 它现在还不能做什么

| 做不到 | 说明 | 以后可以怎么补 |
| --- | --- | --- |
| 点击按钮、切换窗口、模拟键鼠 | 没有 GUI 自动化能力 | 接入 pyautogui / pywinauto |
| 截图、识别屏幕内容 | 没有屏幕捕获能力 | 接入 Pillow / mss |
| 删除到回收站 | 是直接删除 | 改用 send2trash |
| 命令白名单/沙箱 | 只是确认，不是隔离 | 加命令解析与白名单 |
| 操作审计记录 | 只写普通日志 | 加结构化审计表 |
| 逐项确认、改参数 | 只能全部批准/拒绝 | 开放 edit 决策 |
| 查询端口、服务、注册表 | 未封装 | 新增对应工具 |

## 7.1 常见问题

**问：它会不会偷偷执行命令？**

不会。所有修改类操作都会停在确认卡片，你不点批准就不会执行。

**问：我点了"批准执行"，为什么没反应？**

可能原因：

1. 操作本身失败了（比如文件被占用），它会返回失败原因。
2. 页面刷新导致状态丢失，需要重新发起一次请求。
3. 命令执行时间较长，界面在等待（默认最多 60 秒）。

**问：为什么它说"拒绝写入系统保护目录"？**

因为目标路径在 `C:\Windows`、`Program Files`、`ProgramData` 或盘符根目录下。这是硬性保护，换到用户目录即可。

**问：为什么搜索很慢？**

搜索是逐文件读取内容。目录越大、文件越多越慢。可以缩小 `root` 范围，或用 `file_glob` 限定类型。

**问：为什么读文件只返回了一部分？**

单个文件最多读 2 MB，单次最多返回 20000 字符。让它"从第 N 个字符继续读"即可。

**问：关掉浏览器，之前的对话还在吗？**

取决于记忆方式：

- 短期记忆（默认）：关掉或刷新就没了。
- 本地文件：保存在 `memorys/chat_history/`，可以恢复。
- PostgreSQL：存数据库，可以跨设备恢复。

### 8.2 安全阈值

文件顶部常量：

| 常量 | 值 | 作用 |
| --- | --- | --- |
| `_MAX_READ_BYTES` | 2 MB | 单文件读取上限 |
| `_MAX_SEARCH_FILES` | 5000 | 内容搜索最多扫描文件数 |
| `_MAX_SEARCH_FILE_BYTES` | 5 MB | 内容搜索跳过的大文件阈值 |
| `_MAX_RESULT_CHARS` | 8000 | 返回给模型的文本上限 |

代码内还有几处硬编码上限：

| 位置 | 上限 |
| --- | --- |
| `list_directory` | 500 项 |
| `read_text_file` 的 `max_chars` | 50000 |
| `search_files` / `search_text` 的 `max_results` | 200 |
| `list_processes` 的 `top_n` | 100 |
| `run_command` 的 `timeout` | 600 秒 |

### 8.3 确认机制

`CONFIRM_TOOLS` 定义在 [agent/react_agent.py](../agent/react_agent.py)：

```python
CONFIRM_TOOLS = {
    "write_text_file": "写入文件",
    "create_directory": "创建目录",
    "move_path": "移动或重命名",
    "copy_path": "复制文件",
    "delete_path": "删除文件或目录",
    "run_command": "执行系统命令",
    "open_path": "打开文件或网址",
}

hitl_middleware = HumanInTheLoopMiddleware(
    interrupt_on={
        name: {"allowed_decisions": ["approve", "reject"]}
        for name in CONFIRM_TOOLS
    },
    description_prefix="该操作会修改电脑状态，请确认参数后再决定是否执行",
)
```

链路：

1. `HumanInTheLoopMiddleware` 在 `after_model` 检查 `interrupt_on`。
2. 命中后调用 `interrupt()` 挂起图，`stream` 的 `updates` 分支产出 `__interrupt__`。
3. `ReactAgent._stream` 转成 `AgentEvent(type="interrupt", action_requests=[...])`。
4. `app.py` 的 `_render_events` 写入 `st.session_state["pending_hitl"]`。
5. `_render_hitl_block` 渲染卡片；用户点击后调用 `resume_stream(decisions)`。
6. `ReactAgent` 用 `Command(resume={"decisions": [...]})` 恢复图。

### 8.4 新增一个电脑工具

1. 在 `os_tools.py` 用 `@tool(description=...)` 定义函数，返回 `str`。
2. 只读工具直接注册到 `react_agent.py` 的 `tools` 列表。
3. 有副作用的工具同时加入 `CONFIRM_TOOLS`，自动接入确认。
4. 写/删类操作在函数内调用 `_is_protected()`。
5. 路径统一用 `_resolve()` 处理。
6. 更新 `prompts/main_prompt.txt` 的工具清单。

### 8.5 单独测试工具

不调用模型，直接跑工具本身：

```powershell
uv run -m agent.tools.os_tools
```

或在 Python 里：

```python
from agent.tools.os_tools import get_system_info, list_directory

print(get_system_info.invoke({}))
print(list_directory.invoke({"path": "."}))
```

注意：`@tool` 装饰后对象是 `StructuredTool`，要用 `.invoke({...})`，不能直接当函数调用。

### 8.6 当前实现边界

- 保护目录只对写/删/移动生效，读操作不限制。
- `copy_path` 只检查目标，允许从系统目录往外复制。
- `move_path` 同时检查源和目标。
- `list_directory` 只过滤以 `.` 开头的项，不读 Windows 隐藏属性。
- `search_text` 是大小写不敏感的子串匹配，不是正则。
- `run_command` 使用 `shell=True`，无沙箱、无白名单。
- 所有工具同步执行，长任务会阻塞 Streamlit 请求。
